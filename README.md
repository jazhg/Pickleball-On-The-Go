# Pickleball On The Go

Pickleball On The Go is a browser-based virtual pickleball game. Your phone acts as the paddle: its motion sensors detect swings, while a laptop webcam tracks your position on the virtual court. You can practice without a physical ball, paddle, or court.

The current build supports:

- Practice rallies and singles matches to 11, win by two
- Phone-based swing input and laptop keyboard fallback
- Webcam position tracking with local MediaPipe pose estimation
- Server-authoritative ball physics and WebSocket synchronization
- Serves, side-out scoring, diagonal service boxes, two-bounce rules, kitchen volleys, out balls, and double bounces
- Recorded referee voice feedback and in-game rule explanations
- Optional NVIDIA Nemotron swing classification and rally review, with deterministic fallbacks

This is a virtual singles game, not tournament officiating software. Physical foot contact, exact serve mechanics, body hits, and post-volley momentum are only approximated by the available sensors.

## Run locally

Requirements: Node.js 22 or later.

```sh
npm install
npm start
```

Open the URL printed by the server. The default server uses HTTPS so that phone motion permissions work. For laptop-only testing, use:

```sh
npm run dev:http
```

Then open [http://localhost:8443/client-laptop/](http://localhost:8443/client-laptop/). Press Space or use the on-screen controls to test the game without a phone.

## Connect a phone

Phone motion access requires HTTPS. Generate a local certificate once, then start the server:

```sh
brew install mkcert       # if needed
mkcert -install
npm run certs
npm start
```

Open the printed `https://<LAN-IP>:8443/client-phone/` URL on the phone. The phone and laptop must be on the same Wi-Fi network. On iOS, install and trust the `rootCA.pem` generated by mkcert before opening the URL.

On the phone:

1. Tap **Enable motion access**.
2. Hold the phone still briefly for calibration.
3. Swing the phone to hit the ball.

Use **Send test swing** to verify the connection without requesting motion access.

## Two-player setup

Run one server and connect both players to it. Open the laptop page on the host, then use its **Play with a friend** link for the second laptop. Each player opens the phone link shown on their own laptop. Both laptops and phones must use the same server URL and local network.

## Optional Nemotron integration

The game works offline by default. To enable the optional hosted Nemotron integration, set the required NVIDIA API key and start the server with live mode enabled:

```sh
NEMOTRON_LIVE=1 NVIDIA_API_KEY=... npm start
```

The integration can classify swings and review rally events. Model responses are schema-validated and cannot directly modify authoritative game state. Timeouts, unavailable services, or invalid responses use labeled deterministic fallbacks.

## Architecture

- **Phone client:** reads motion and sends swing events over WebSockets.
- **Laptop client:** renders the court and ball with Three.js, tracks pose, and displays the HUD.
- **Relay server:** owns the simulation, scoring, player state, and event log.
- **Nemotron bridge:** optionally classifies shots and reviews rule events asynchronously.

The server runs the simulation at 120 Hz and broadcasts state at 60 Hz. Video is processed locally; only estimated pose data is sent to the relay.

## Evaluation and limitations

The `nemotron/` directory contains the referee schema, synthetic fixtures, evaluation harness, and deterministic baselines. The included fixtures are regression tests, not an independently human-labeled benchmark. The current rule configuration still requires human review before its citations should be treated as authoritative.
